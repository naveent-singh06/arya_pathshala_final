# ARYA PATHSHALA - Phase 1 setup (AI Tutor)

What you need to configure yourself. No secret values belong in this repository.

## 1. Firebase (your existing project)
1. **Authentication**: Google sign-in stays as it is. Add your Vercel domain under
   *Authentication -> Settings -> Authorized domains*, or Google sign-in will fail on the live site.
2. **Firestore**: *Build -> Firestore Database -> Create database*. Do not enable Storage yet (Phase 2).
3. **Rules**: publish `firestore.rules` (Firestore -> Rules, or `firebase deploy --only firestore:rules`).
   Students can only read/write their own chats; the `tutorUsage` counters are server-only.
4. **Service account** (server only): *Project settings -> Service accounts -> Generate new private key*.
   Paste the whole JSON (or its base64) into the `FIREBASE_SERVICE_ACCOUNT_JSON` environment variable.
   Never commit this file.

## 2. AI provider
Any OpenAI-compatible chat-completions API. Default is Groq with `llama-3.3-70b-versatile`.
Create a key at https://console.groq.com and set `LLM_API_KEY`.
To switch provider or model, change only `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`.
Check the provider's model list from time to time; providers retire models.

## 3. Vercel environment variables
Add every name from `.env.example` in *Project Settings -> Environment Variables*:
the `REACT_APP_FIREBASE_*` values (public by design) and the server-only values
(`LLM_*`, `TUTOR_*`, `FIREBASE_SERVICE_ACCOUNT_JSON`). `vercel.json` already routes the website
to `index.html` and allows `/api/tutor` up to 60 seconds.

## 4. Running locally
`npm start` only serves the website. To run the website **and** `/api/tutor` together use
`npx vercel dev` with a `.env.local` file made from `.env.example`.

## 5. Deployment architecture (what runs where)
- **Vercel** hosts only the React website and the `/api/tutor` serverless function (Node 22).
  `vercel.json` pins the build (`npm ci`, `npm run build`, output `build/`) and `.vercelignore`
  keeps the Python backend and other non-website folders out of the Vercel build.
- **The Python backend** (`backend/`: face-recognition attendance, grading assistant, study planner)
  is **not** deployed by Vercel. Its dependencies (torch, ultralytics, opencv...) are several GB, and face
  recognition reads a camera on the server. Its package list is `backend/requirements.txt`
  (moved from the repository root so Vercel no longer detects a Python project and installs it).
  Run it on a separate host: `pip install -r backend/requirements.txt` then `python backend/app.py`
  (use Python 3.11 or 3.12; `pandas==2.2.2` does not build on newer Python versions).
- **Not connected yet:** the website still calls the Python backend at `http://localhost:5000`
  (FaceRecog, Planner and Grading Assistant). Those three features work only when the backend runs on the
  same computer as the browser, until a backend URL setting is added in a later step.
- `authentication-backend/` (Node + MongoDB) is unused by the website and is not deployed.

## 6. Tests
- `npm run test:api` - server API tests (no network or keys needed).
- `CI=true npm test` - React tests.
- `npm run build` - production build.

## Known limits (Phase 1)
- The Firestore security rules have been reviewed by hand but not run in the Firebase emulator.
- The AI answers are generated by a language model and can be wrong; the tutor says so and asks
  students to verify important answers. Image/PDF questions, voice and study-material search (RAG)
  are planned for later phases and are not in this release.
- Usage limits are per student: `TUTOR_RATE_PER_MINUTE` (default 8) and `TUTOR_DAILY_LIMIT` (default 100).

## 7. If the AI Tutor says it is unavailable
Open `https://<your-site>/api/tutor-status` in a browser. It lists, without showing any value, whether `LLM_API_KEY` and
`FIREBASE_SERVICE_ACCOUNT_JSON` are `present`, `missing` or `invalid`, plus the provider host and model. If both are present,
sign in as admin and call `/api/tutor-status?probe=1` with your ID token to test the real provider key and Firestore.
- `llmApiKey: missing` -> add `LLM_API_KEY` (server-only; no `REACT_APP_` prefix) in Vercel -> Settings -> Environment Variables, for **Preview and Production**.
- `firebaseServiceAccount: missing/invalid` -> add `FIREBASE_SERVICE_ACCOUNT_JSON` (whole JSON or its base64) for Preview and Production. It must be a key of the SAME Firebase project the website uses.
- Firestore must be created (otherwise usage limits fail with "can't check usage limits").
- **Environment variable changes only apply to a new deployment**: redeploy after adding them.
- An error 404/401 from the website host (not a Tutor message) means the function is not deployed or Vercel Deployment Protection is blocking it.
